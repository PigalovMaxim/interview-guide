# Interview Guide

Сайт на HTML, CSS и JavaScript. Откройте `index.html` двойным кликом или через локальный сервер. Установка пакетов и сборка не требуются: данные подключены script-тегами, без fetch.

## Состав редакции 4

540 материалов: 45 технических вопросов EasyOffer, 40 вопросов из [YauhenKavalchuk/interview-questions](https://github.com/YauhenKavalchuk/interview-questions), 395 редакционных кейсов проекта и 60 сохранённых практических задач. Вопросы о личном опыте и другие нетехнические позиции не включены.

В каждой из девяти тем на каждой из четырёх вкладок 15 карточек. Сложные кейсы имеют отдельный ожидаемый уровень. Начальная тема — JavaScript. Счётчики, покрытие и итоги рассчитываются из фактического состава.

У сторонних вопросов исходная формулировка сохранена в `title` и `question`; сняты только обратные кавычки Markdown у GitHub. Повтор одного вопроса EasyOffer в разных уровнях — отдельные карточки `easyoffer:{level}:{sourceId}`. Уровень совпадает с уровнем списка источника; редакционный разбор, критерии и уточнения адаптированы к нему. У вопросов GitHub сохранены ID из манифеста и прямая ссылка на строку в конкретном коммите.

Ссылки на EasyOffer и GitHub показаны рядом с вопросом. Кейсы проекта отмечены как редакционные. `references` содержат первичную документацию для технической сверки, а `verifiedAt` — дату сверки конкретного материала.

## Интервью и хранение

Оценки опубликованных карточек сохраняются при переходе с редакции 3 на 4 и хранятся в `interview-guide.ratings.v3`. Прежние ключи `interview-guide.ratings` и `interview-guide.ratings.v2` не импортируются, не изменяются и не удаляются. Даже совпадающие ID практических задач не переносят старые оценки. При наличии любого архива показывается пояснение. Оформление использует прежний `interview-guide.theme`.

«Очистить оценки» после подтверждения удаляет только текущее интервью. Повреждённые новые данные защищены от автоматической перезаписи до явной очистки; при недоступном хранилище сайт работает в памяти и сообщает об ограничении.

В карточке сначала идёт «Спросите кандидата». После самостоятельного ответа интервьюер выбирает одну ветку `support` или `transfer`. Поле `expected` — ориентир интервьюеру, его не зачитывают. «Уверенно» требует самостоятельного ответа на основной вопрос, «Глубоко» — также переноса на изменённую ситуацию. Помощь не доказывает глубину; обоснованные альтернативы допустимы. Эти оценки не присваивают грейд автоматически.

Практические задачи раскрывают разбор отдельно. Копирование содержит только заголовок, вопрос, точные условия, примеры и стартовый код — независимо от раскрытия решения. При запрете буфера доступен ручной текст. Сохранены все 60 задач, их ID, формулировки, критерии и уточнения. Единственная коррекция: решение `v2:coding:calendar-date` сразу возвращает `false`, если `typeof text !== "string"`; boxed String и объекты больше не принимаются и не приводятся к строке. Остальные решения и все остальные поля задач неизменны. Контрольные суммы обновлены только для этой карточки и файла.

Раздел «Итоги» показывает четыре круговые диаграммы. Доля сектора — доля темы среди оценённых материалов уровня, включая «Не ответил». Неоценённые материалы исключены из диаграммы. Легенда содержит девять тем, выбор показывает четыре оценки и покрытие X/N, где N — число материалов группы (15). Доля не означает процент знания. Навигация между вопросами и итогами сохраняет раскрытия и оценки в одном документе.

## Файлы и проверки

- `data/catalog.js` — редакция, ключ хранения, темы, вкладки и методика.
- Остальные `data/*.js` — материалы, `coding.js` содержит сохранённую практику.
- `app.js` — навигация, источники, раскрытия, пустые состояния, копирование.
- `store.js` — хранение и защита архивов, `results.js` — фактические размеры групп и диаграммы.
- `../data-sources/` — snapshots источников, исходные редакционные разборы и контрольные суммы. JSON намеренно находится вне `web/data`: helper тестов исполняет все файлы этой папки.

Из корня: `node data-sources/build-bank.cjs` пересобирает восемь тематических файлов. Редакционные кейсы хранятся в `../data-sources/project-editorial-cases.json`; изменение состава требует технической сверки и сохранения 15 карточек на группу; изменение порядка не должно менять ID. Практический файл генератор не трогает.

`node --test tests/*.test.js` проверяет точное соответствие источникам, отклонённые записи, уровни, полноту разбора, ordinal, контрольные суммы практики с указанной коррекцией и сохранность архивов, исполняет решения всех 60 задач. `tests/generation.test.js` в изолированной временной копии запускает настоящий генератор, сравнивает результат с поставляемым банком, проверяет неизменность `coding.js` при генерации и отказ до записи при неверной теме/уровне. Реестр `javascript-output.json` покрывает исполняемые примеры JavaScript из редакционных кейсов.

`node tests/browser-check.cjs` использует внешние Playwright (`PLAYWRIGHT_MODULE`) и Chromium/Edge (`BROWSER_PATH`). Проверяет 36 сочетаний по 15 карточек, источники, ветки, копирование всех задач, v3 и сохранность v1/v2, итоги, клавиатуру, мобильную ширину и file://. Снимки сохраняются в `QA_SCREENSHOT_DIR` либо временной папке. React, Redux и TypeScript — темы интервью, не зависимости реализации сайта.
