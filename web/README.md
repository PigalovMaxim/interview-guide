# Interview Guide

Сайт на HTML, CSS и JavaScript. Откройте `index.html` двойным кликом или через локальный сервер. Установка пакетов и сборка не требуются: данные подключены script-тегами, без fetch.

## Состав редакции 3

145 материалов: 45 технических вопросов EasyOffer, 40 отобранных вопросов [YauhenKavalchuk/interview-questions](https://github.com/YauhenKavalchuk/interview-questions), 60 сохранённых практических задач с одной коррекцией решения `calendar-date`. EasyOffer ограничивает публичный ответ 20 позициями на уровень; после исключения опыта, мотивации, зарплаты, вопросов к компании и карьерных планов осталось 18 Junior, 14 Middle и 13 Senior. Это не весь каталог. GitHub-дополнение содержит 14 Junior, 14 Middle и 12 Senior, заполняет пробелы и не копирует видеоответы.

Сохранены девять тем и четыре вкладки. Начальная тема — JavaScript. TanStack Query не представлен в подборках; «Сложные вопросы» содержат только 15 прежних практических задач. В пустых сочетаниях показывается сообщение и 0 материалов. Все счётчики, покрытие и итоги рассчитываются из фактического состава.

Точная исходная формулировка вопроса сохранена в `title` и `question`; сняты только Markdown-backticks у GitHub. Повтор одного вопроса EasyOffer в разных уровнях — отдельные карточки `easyoffer:{level}:{sourceId}`. Уровень совпадает с уровнем списка источника; редакционный разбор, критерии и перенос адаптированы к нему. У GitHub сохранены ID manifest и permalink с commit/строкой.

Происхождение вопроса (`source`) показано рядом с вопросом. Ответ, объяснение, критерии и две ветки уточнений — самостоятельные редакционные материалы приложения; это явно подписано в UI. `references` содержат первичную документацию для технической сверки, а `verifiedAt` — её дату, 17.11.2026 для новых вопросов. Дата получения вопроса остаётся 16.11.2026. У практических задач сохранены исходные даты и все поля, кроме согласованной проверки типа в `solution.code` задачи `calendar-date`.

## Интервью и хранение

Оценки относятся к текущему интервью редакции 3 и хранятся в `interview-guide.ratings.v3`. Прежние ключи `interview-guide.ratings` и `interview-guide.ratings.v2` не импортируются, не изменяются и не удаляются. Даже совпадающие ID практических задач не переносят старые оценки. При наличии любого архива показывается пояснение. Оформление использует прежний `interview-guide.theme`.

«Очистить оценки» после подтверждения удаляет только текущее интервью. Повреждённые новые данные защищены от автоматической перезаписи до явной очистки; при недоступном хранилище сайт работает в памяти и сообщает об ограничении.

В карточке сначала идёт «Спросите кандидата». После самостоятельного ответа интервьюер выбирает одну ветку `support` или `transfer`. Поле `expected` — ориентир интервьюеру, его не зачитывают. «Уверенно» требует самостоятельного ответа на основной вопрос, «Глубоко» — также переноса на изменённую ситуацию. Помощь не доказывает глубину; обоснованные альтернативы допустимы. Эти оценки не присваивают грейд автоматически.

Практические задачи раскрывают разбор отдельно. Копирование содержит только заголовок, вопрос, точные условия, примеры и стартовый код — независимо от раскрытия решения. При запрете буфера доступен ручной текст. Сохранены все 60 задач, их ID, формулировки, критерии и уточнения. Единственная коррекция: решение `v2:coding:calendar-date` сразу возвращает `false`, если `typeof text !== "string"`; boxed String и объекты больше не принимаются и не приводятся к строке. Остальные решения и все остальные поля задач неизменны. Контрольные суммы обновлены только для этой карточки и файла.

Раздел «Итоги» показывает четыре круговые диаграммы. Доля сектора — доля темы среди оценённых материалов уровня, включая «Не ответил». Неоценённые материалы исключены из диаграммы. Легенда содержит девять тем, выбор показывает четыре оценки и покрытие X/N, где N — реальное число материалов группы, включая 0. Доля не означает процент знания. Навигация между вопросами и итогами сохраняет раскрытия и оценки в одном документе.

## Файлы и проверки

- `data/catalog.js` — редакция, ключ хранения, темы, вкладки и методика.
- Остальные `data/*.js` — материалы, `coding.js` содержит сохранённую практику.
- `app.js` — навигация, источники, раскрытия, пустые состояния, копирование.
- `store.js` — хранение и защита архивов, `results.js` — фактические размеры групп и диаграммы.
- `../data-sources/` — snapshots источников, исходные редакционные разборы и контрольные суммы. JSON намеренно находится вне `web/data`: helper тестов исполняет все файлы этой папки.

Из корня: `node data-sources/build-bank.cjs` пересобирает восемь тематических файлов. Добавление карточек требует записи в manifest, самостоятельного разбора и технической сверки; изменение порядка не должно менять ID. Практический файл генератор не трогает.

`node --test tests/*.test.js` проверяет точное соответствие источникам, отклонённые записи, уровни, полноту разбора, ordinal, контрольные суммы практики с указанной коррекцией и сохранность архивов, исполняет решения всех 60 задач. `tests/generation.test.js` в изолированной временной копии запускает настоящий генератор, сравнивает результат с поставляемым банком, проверяет неизменность `coding.js` при генерации и отказ до записи при неверной теме/уровне. Реестр `javascript-output.json` пуст: в новых теоретических карточках нет отдельных исполняемых `questionCode`; примеры удалённых карточек не выполняются.

`node tests/browser-check.cjs` использует внешние Playwright (`PLAYWRIGHT_MODULE`) и Chromium/Edge (`BROWSER_PATH`). Проверяет 36 сочетаний с переменными размерами и пустыми группами, источники, ветки, копирование всех задач, v3 и сохранность v1/v2, итоги, клавиатуру, мобильную ширину и file://. Снимки сохраняются в `QA_SCREENSHOT_DIR` либо временной папке. React, Redux и TypeScript — темы интервью, не зависимости реализации сайта.
