# Критерии приёмки и сохранение требований

Обязательное приложение к [SPEC.md](SPEC.md). Сценарии ниже предназначены для будущей реализации: их наличие не означает, что сайт или контент уже прошли проверку. Допущения A-1…A-4 действуют до явного пересмотра.

## Сценарии

| ID | Связь | Проверка | Ожидаемый результат |
| --- | --- | --- | --- |
| AC-01 | CAP-1 | Перечислить все пары вкладка/тема и проверить каталог. | 4 вкладки × 9 тем; в каждой 15 материалов с уникальными позициями 1–15; всего 540 уникальных устойчивых ID. |
| AC-02 | CAP-1, A-1 | Проверить уровень и происхождение карточек в каждой теме. | Junior проверяет основы, Middle — применение, Senior — решения при ограничениях. В каждой группе сначала идут вопросы из подборок, затем редакционные кейсы. В сложной вкладке есть оба ракурса и целевые уровни. Переименованных дублей и заглушек нет. |
| AC-03 | CAP-2 | Проверить обязательные поля всего банка; открыть обычный вопрос. | Краткий ответ, подробный разбор, предметные критерии basic/confident/deep и ровно 2–3 уточнения заполнены и доступны. Версионные зависимости явно описаны. |
| AC-04 | CAP-1, CAP-2, A-2 | Открыть страницу, две карточки, сменить тему и уровень. | Начало Junior/JavaScript; карточки свёрнуты. Несколько раскрытий возможны; смена списка сбрасывает раскрытия, сохраняет тему при смене уровня и не стирает оценки. |
| AC-05 | CAP-3 | Открыть задачу, затем её разбор, свернуть и открыть заново. | Сначала только кандидатская часть; краткий ответ и решение не показаны. Отдельно доступны решение, крайние случаи и сложность. После повторного открытия разбор снова скрыт. |
| AC-06 | CAP-3, A-2 | Скопировать многострочный код и всю задачу в внешний текстовый редактор при закрытом и открытом разборе. | Код сохраняет отступы и переносы без номеров строк; полное задание содержит условие, примеры и стартовый код. Ни в одном случае нет решения, оценочных критериев или подсказок. |
| AC-07 | CAP-3, A-3 | Смоделировать отказ копирования. | Не показывается успех; есть понятное сообщение и возможность вручную выделить и скопировать текст. |
| AC-08 | CAP-4 | Оценить разные вопросы всеми четырьмя значениями, изменить одну оценку, свернуть карточку. | У каждого вопроса одно независимое значение; изменение заменяет его; отметка видна в свёрнутом виде; неоценённые вопросы не стали «не ответил». |
| AC-09 | CAP-5, A-3 | Поставить оценки в разных темах/уровнях, переключить списки, перезагрузить страницу. | Все оценки восстановлены по ID; стартовое пустое состояние их не затёрло. Перестановка карточки без смены ID не меняет привязку. |
| AC-10 | CAP-5, A-3 | Подать неизвестный ID, неверное значение, повреждённое сохранение, неизвестную версию формата и отказ записи. | Валидные записи не теряются из-за единичной плохой; повреждённый/неизвестный формат не перезаписывается автоматически. Приложение не падает, объясняет ограничение и не обещает сохранение при ошибке. |
| AC-11 | CAP-6 | При оценках в нескольких вкладках отменить очистку, затем подтвердить и перезагрузить. | Отмена ничего не меняет; подтверждение очищает все оценки, включая скрытые разделы. После перезагрузки везде «без оценки», оформление прежнее. Контент не меняется. |
| AC-12 | CAP-6, A-3 | Повторить очистку пустого интервью и смоделировать отказ удаления сохранения. | Пустой сброс безопасен. При отказе показано, что сохранённые результаты могли остаться; безусловного сообщения об успехе нет. |
| AC-13 | CAP-7, A-2 | Переключить тему на открытой карточке с оценкой, перезагрузить, затем очистить оценки. | Обе темы работают; выбор оформления сохраняется. Переключение не меняет оценку и раскрытие; очистка не сбрасывает оформление. Тёмная база соответствует трём заданным цветам. |
| AC-14 | CAP-2, CAP-3, CAP-7, A-4 | Проверить обе темы, клавиатуру, уменьшение движения, ширины 360/1280 px и масштаб 200% в широком окне. | Доступны все действия; фокус видим, скрытые ответы недоступны фокусу; значения имеют подписи. Движение отключается по предпочтению. Текст и код читаемы, контраст не ниже 4.5:1, код не расширяет страницу. |
| AC-15 | CAP-1…CAP-7 | Выполнить сквозной сценарий из Success signal на полном проверенном банке. | Интервьюер может выбрать материал, оценить ответ, передать задачу и начать новое интервью без смешения результатов; сайт не требует истории кандидатов или встроенного выполнения кода. |

Для AC-02 и содержательной части AC-03 нужен редакционный просмотр, а не только автоматическая проверка полей. Для задач отдельно проверить работоспособность примеров и решений в целевой среде вне сайта. Финальная приёмка полного объёма невозможна на демонстрационных карточках.

## Карта сохранения исходных требований

| Утверждение Forge | Где сохранено |
| --- | --- |
| Интервьюер оценивает глубину понимания по объяснениям и уточнениям. | Why; CAP-2, CAP-4; content-model.md / Общая карточка. |
| Четыре вкладки и все перечисленные технологии, архитектура/FSD и программирование. | CAP-1; content-model.md / Матрица наполнения. |
| Увеличение 10 → 15 и рост сложности, разные стартовые планки уровней. | CAP-1; Constraints; content-model.md / Градация. |
| Инженерные кейсы и каверзные нюансы нужны вместе. | Constraints; content-model.md / Градация. |
| 540 материалов — банк для выбора, не обязательный полный опрос. | Why; Constraints; content-model.md / Матрица наполнения. |
| Изначальная свёрнутость, плавное раскрытие, красивый спокойный дизайн. | CAP-2, CAP-7; interaction-rules.md / Навигация; visual-requirements.md. |
| Краткий ответ, подробный разбор, три глубины понимания, 2–3 уточнения. | CAP-2; content-model.md / Общая карточка. |
| Условия, примеры, код, решение, крайние случаи, сложность задач. | CAP-3; content-model.md / Дополнение для task. |
| Внешний редактор, подсветка, копирование, отдельное решение без утечки в задание. | CAP-3; interaction-rules.md / Копирование задачи. |
| Четыре оценки и отдельное состояние без оценки. | CAP-4; interaction-rules.md / Оценка. |
| Стор и локальное сохранение между вкладками и перезагрузками. | CAP-5; interaction-rules.md / Модель состояния и Восстановление. |
| Одно интервью, очистка всех результатов с подтверждением и сохранением оформления. | CAP-6; interaction-rules.md / Очистка. |
| Обе мягкие темы; референс Atom One Dark; светлая не чёрная на белом. | CAP-7; Constraints; visual-requirements.md / Палитра. |
| Нужны проверка 540 материалов, версии контента, макет и выбор стека. | content-model.md / Проверка наполнения; Q-1…Q-3. |
| Нет редактора/выполнения кода, истории кандидатов, дословных записей или автогрейда. Поиск и избранное не согласованы. | Non-goals. |
| Исходные предложения, не подтверждённые отдельно: целевые уровни сложных вопросов, две команды копирования, запоминание темы. | A-1, A-2; соответствующие приложения. |

Имена персон Forge, печать результата, история установки и операционные инструкции навыков не влияют на продукт; они исключены как служебное оформление. Отменённые 10 вопросов заменены действующим требованием 15; старый вариант не является параллельным условием.

## Граница готовности

Спецификация пригодна для планирования и UX с явно указанными допущениями. Q-1 закрывается при подготовке макета, Q-2 — перед реализацией, Q-3 — перед массовой подготовкой банка. Сам этот документ не подтверждает выполнение AC-01…AC-15; результаты будущих проверок должны иметь отдельные свидетельства.
